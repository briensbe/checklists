# Checklists — contexte pour Claude Code

Application Angular 100 % navigateur pour créer des modèles de checklists (builder) et les exécuter (audits, mises en production). Aucune donnée ne quitte le poste : tout est stocké dans IndexedDB.

## Où trouver quoi

- [.agents/AGENTS.md](.agents/AGENTS.md) : règles techniques générales (pnpm, Angular, typage, langue, Markdown).
- [README.md](README.md) : fonctionnalités, commandes, organisation du code.
- [openspec/specs/](openspec/specs/) : comportement attendu, **source de vérité**. Toute évolution passe par un change OpenSpec (`/opsx:propose`).
- [adr/](adr/) : décisions d'architecture en vigueur.
- [openspec/HANDOVER.md](openspec/HANDOVER.md) : feuille de route et contexte d'architecture commun ; [openspec/BACKLOG.md](openspec/BACKLOG.md) : idées reportées.
- [docs/design/checklist-ux.md](docs/design/checklist-ux.md) et [docs/design/mockups/](docs/design/mockups/index.html) : vision UX et maquettes. Référence de **comportement**, non normative : lire d'abord la section « Écarts retenus », puis transposer dans le modèle et la charte existants au lieu de recopier.
